## 1. 全体アーキテクチャ

単一APK・3層構成(UI: Compose+Material 3 / Domain / Data)+ システム連携コンポーネント。v1.0 から構成変更なし。

```
UI: Home / StartFlow(3step) / BookList / BlockSettings(Apps|Sites) /
    History(月カレンダー) / SetupWizard / LockOverlay(WindowManager)
Domain: SessionEngine / LockPolicy / ProgressCalculator /
        LogicalDayResolver / StreakCalculator / FaceDownDetector
Data: Room + DataStore
System: MonitorService(FGS) / DnsVpnService / ScreenStateReceiver /
        BootReceiver / ResetScheduler(4:00)
```

## 2. コンポーネント責務(v1.0 からの差分のみ)

- **FaceDownDetector**(新規): 紙セッション中のみ SensorManager を購読。近接センサー(near)+加速度(Z軸 ≈ −9.8 m/s²)で「伏せ状態」を判定。画面OFFも伏せと同等に扱う。持ち上げ/画面タッチ検知で猶予10秒後に PAUSE イベントを発火。セッション外ではセンサー購読を完全停止(電池対策)
- **StreakCalculator**(新規): DailyProgress から連続達成日数を算出。当日はまだ未達成でもストリークを切らない(判定は論理日確定時)
- **AppWatcher / LockController / DnsVpnService**: v1.0 のまま。前面検知は UsageStatsManager ポーリングを正とする(ハンドオフに AccessibilityService の記載があるが、審査不要の野良APKでもポーリングで要件を満たせるため採用しない。検知精度に問題が出た場合の代替手段として §9 に残す)

## 3. コアルール(ドメインロジック確定版)

- ノルマ: デフォルト30分/日。達成までブロック有効
- ノルマ変更: **延長 → 即時反映 / 短縮 → 翌日4:00 から反映**(pending値として保持)
- 計上対象: 「ソース選択 →(Kindle/DMMは)本の宣言 → セッション開始」を踏んだ実効時間のみ。セッション中の本変更は不可
- 達成後: その論理日の終わりまでロック解除。セッション継続・追加セッション(「続けて読む」)可。実績は記録し続ける
- 日次リセット: **毎日 4:00**。進捗0分・ロック再有効化・DNSフィルタ再適用
- ストリーク: 達成日の連続数。履歴とホーム(達成時)に表示

## 4. 計測ロジック

### 4.1 Kindle / DMM
- セッション RUNNING 中、前面が対象アプリ(`com.amazon.kindle` / DMM Books ※パッケージ名実機確認)の間だけ加算(1秒粒度、内部は秒で保持)
- 対象外アプリの前面化 → 自動 PAUSE + 通知「他のアプリの操作を検知しました」。対象アプリ復帰で自動 RESUME(自アプリの計測画面に戻る必要なし)

### 4.2 紙の本(伏せ検知方式)
- 計測中画面で30分カウントダウンを表示
- **カウント条件**: 伏せ状態(近接 near + Z軸下向き) OR 画面OFF
- 開始: セッション開始後、最初に伏せ/画面OFFを検知した時点からカウント
- 停止: 持ち上げ・画面タッチを検知 → 10秒猶予 → PAUSE。再び伏せれば自動 RESUME
- 画面OFF区間は実時間差分で一括加算(センサーは近接のみ低頻度購読、電池負荷最小化)
- 着信対応: 特別処理なし。応答のため持ち上げれば通常ルールで PAUSE、通話後に伏せれば再開(§9-5)

## 5. ブロック機構

### 5.1 ロックオーバーレイ(確定仕様)
- 表示条件: 前面アプリ ∈ BlockedApp(enabled) AND 本日未達成 AND ホワイトリスト外
- 表示内容: ブロックしたアプリ名 / 残り分数リング / 「あと◯分の読書で解禁されます」 / 今日の進捗(12/30分)
- ボタンは2つのみ(閉じる・スキップ・戻る操作は一切無効化):
  1. **読書を開始** → 開始フロー(ソース選択)へディープリンク
  2. **読書ロックを開く** → ホームへ
- 戻るジェスチャー/ボタンは消費して無視(OnBackPressedCallback / キーイベント消費)

### 5.2 サイトブロック
- v1.0 の DNS フィルタ設計(サフィックス一致・NXDOMAIN応答・DoH対策)を踏襲
- **ドメイン追加は即時反映 / 削除は翌日4:00 に実行**(pendingDeleteAt で予約)

## 6. データモデル v2

```kotlin
@Entity(tableName = "books")
data class Book(
  @PrimaryKey(autoGenerate = true) val id: Long = 0,
  val title: String,
  val source: Source,               // KINDLE / DMM / PAPER
  val status: BookStatus,           // ACTIVE / ARCHIVED
  val lastReadAt: Long?,            // 「前回の続き」表示用
  val createdAt: Long
)

@Entity(tableName = "reading_sessions")
data class ReadingSession(
  @PrimaryKey(autoGenerate = true) val id: Long = 0,
  val bookId: Long?,                // PAPERは任意
  val source: Source,
  val logicalDate: String,          // 4:00境界の論理日
  val startedAt: Long,
  val endedAt: Long?,
  val effectiveSeconds: Int = 0,    // 一時停止を除いた実効秒(UI表示は分)
  val state: SessionState,          // RUNNING / PAUSED / ENDED
  val pausedReason: PauseReason?,   // OTHER_APP / PICKED_UP / MANUAL / null
  val lastHeartbeatAt: Long         // 復元用(§9-2)
)

@Entity(tableName = "daily_progress")
data class DailyProgress(
  @PrimaryKey val logicalDate: String,
  val totalSeconds: Int = 0,
  val quotaMinutes: Int,            // その日に適用されたノルマ(履歴の正確性のため凍結保存)
  val achievedAt: Long? = null
)

@Entity(tableName = "blocked_apps")
data class BlockedApp(
  @PrimaryKey val packageName: String,
  val appName: String,
  val enabled: Boolean = true,
  val addedAt: Long
)   // 直近7日使用時間は保存せず、表示時に UsageStats から都度取得

@Entity(tableName = "blocked_domains")
data class BlockedDomain(
  @PrimaryKey val domain: String,
  val addedAt: Long,
  val pendingDeleteAt: Long? = null // 翌日4:00の削除予約。nullなら有効
)

@Entity(tableName = "session_events")   // 宣言・一時停止の監査ログ(v1.0踏襲)
data class SessionEvent(
  @PrimaryKey(autoGenerate = true) val id: Long = 0,
  val sessionId: Long,
  val type: EventType,  // DECLARE/START/AUTO_PAUSE/RESUME/END/FORCE_END_RESET/RESTORED
  val at: Long
)
```

DataStore: `quota_minutes` / `quota_minutes_pending`(翌日反映値)/ `theme` / `setup_completed_steps`(Bitフラグ)/ `paper_grace_seconds=10`

シード: v1.0 と同一(X・Facebook / 指定4ドメイン)。

## 7. 常駐通知

- 通常: 「読書 12/30分 ─ ロック中」+ ProgressBar + アクション「読書を開始」
- 達成: 「今日の読書 30/30分 ✓ ─ ロック解除中」(バー満了・色変化)
- チャンネル分離: 常駐(LOW・無音)/ イベント通知(達成・一時停止検知はDEFAULT)

## 8. セットアップウィザード

4ステップ(使用状況 → オーバーレイ → 電池最適化除外 → VPN)。各ステップの許可状態は毎回実チェックし(保存フラグだけに頼らない)、剥奪検知時は §9-3 のフローで再誘導。

## 9. エッジケース設計判断(ハンドオフ§8への回答)

1. **4:00またぎセッション**: リセット時に強制 END(FORCE_END_RESET)。実効秒は前論理日に計上。継続したい場合は再宣言(1タップで直前の本を再選択できる導線を計測画面に用意)
2. **再起動・プロセスキル復元**: RUNNING/PAUSED セッションは10秒ごとに effectiveSeconds と lastHeartbeatAt を永続化。サービス再起動時、未ENDセッションが残っていれば **PAUSED として復元**し(RESTORED イベント記録)、通知「セッションを復元しました。再開してください」を表示。lastHeartbeat から4:00を跨いでいた場合は前論理日で強制END
3. **権限の事後剥奪**: MonitorService が60秒ごとに4権限をセルフチェック。欠落検知 → ロック機能は fail-closed にせず(オーバーレイ不能時にSNSを塞げないのは仕方ない)、**最優先の警告通知+ホームに赤バナー**でウィザード該当ステップへ誘導。使用状況権限の欠落時は計測も止まる旨を明示
4. **VPN競合**: 他アプリがVPNを張ると `onRevoke()` が呼ばれる → サイトブロック無効を警告通知+ホームバナーで表示。自動再接続は試みない(VPN の奪い合いはOS仕様上不毛)。運用ルールとして他VPNとの併用不可を設定画面に明記
5. **紙セッション中の着信・アラーム**: 専用処理なし。持ち上げ=通常の PAUSE ルール(10秒猶予)で吸収。アラーム鳴動のみ(端末放置)なら伏せ状態が続くためカウント継続で問題なし
